# 本机扫描仪接入

InteSchool 在浏览器中无法直接调用 TWAIN、WIA 或 SANE 扫描仪驱动。连接扫描仪的电脑必须安装驱动并启动**本机扫描桥接程序**。网页里的学校绑定仅用于筛选已发布答题卡；上传及后续处理扫描记录则必须登录对应学校的教师账号。

## Windows：一键安装（推荐）

1. 在学校的 InteSchool 网页中打开“我要扫描”。当本机服务不可用时，点击 **下载 Windows 安装包**，安装 `InteSchool-Scanner-Setup.exe`。支持 Windows x64，无需另外安装 Node.js 或手动配置服务来源；安装完成后自动启动，并在 Windows 通知区域（右下角，可能位于「^」隐藏图标中）显示 InteSchool 图标；以后登录 Windows 时自动运行。服务仅监听 `127.0.0.1:17380`。
2. 返回扫描页面点击 **授权连接本站**，浏览器弹窗选择打开 InteSchool 扫描桥接，在 Windows 确认框检查网站来源并点击“是”。该授权仅赋予确认过的网站本地扫描权限，其他站点会被桥接拒绝。
3. 鼠标双击右下角 InteSchool 图标，可打开已授权网站的扫描页。右键菜单可检查服务状态、重新启动扫描服务、打开诊断日志，以及打开 NAPS2 官方安装页。配置和授权仍从网站进行。点击网页 **刷新设备**。安装扫描仪厂商驱动后即可使用。需要 TWAIN 双面自动进纸时还需安装 [NAPS2](https://www.naps2.com/)（或使用设备厂商支持的 WIA 通道）；NAPS2 安装在默认路径时可自动检测。

若出现 Windows SmartScreen 未知发布者提示，安装包尚无代码签名，请先从官方发布页核对来源及 SHA256 校验和，切勿运行来源不明的程序。

## 不安装桥接程序：导入系统扫描结果（任意操作系统）

现代浏览器没有通用 TWAIN/WIA/SANE 接口，因此**无法保证任何电脑只打开网页就能直接驱动任意 USB 扫描仪**。若无法安装 InteSchool 扫描桥接，在 Windows 扫描、macOS 图像捕捉、Linux simple-scan/NAPS2 或扫描仪厂商软件中扫描为 **PNG/JPEG**，再打开 InteSchool 的“我要扫描”页面：

1. 绑定学校，找到正确的已发布答题卡，点击该卡片的 **导入图片**（桥接离线时依旧可用）。
2. 一次选择多张图片（最多 40 页；每张不超过 25 MB，单批最多 120 MB）。系统按照文件选择顺序预览并核对二维码；需要追加时点击 **继续导入图片**。
3. 核对试卷归属后，用本校教师账号登录并点击 **确认试卷并上传**。扫码识别到其他试卷的图像仍会被拦截。
4. 第三方卡可登录教师账号后点击 **导入第三方卡图片**，选择单张 PNG/JPEG 图片，然后保存到作业管理。

这个方案无需安装 InteSchool 客户端，但实际驱动扫描仪的步骤仍由操作系统或厂商软件完成。PDF/TIFF 文件需要先转成 PNG/JPEG。导入图片与本机扫描使用相同的二维码校验和服务器上传权限控制。

## 开发者：从源码启动

1. 安装 Node.js 22 或更新版本，克隆 InteSchool 仓库。
2. Windows 安装扫描仪设备驱动；需要 TWAIN 时安装 [NAPS2](https://www.naps2.com/)。
3. Linux 安装 `sane-utils` 和设备对应的 SANE 后端，检查 `scanimage -L`。
4. 在仓库根目录启动扫描桥接；`SCANNER_ALLOWED_ORIGIN` 必须与浏览器地址栏的实际来源完全一致（协议、域名和端口）：

```powershell
$env:SCANNER_ALLOWED_ORIGIN = "https://你的InteSchool域名"
node scripts/scanner-bridge.mjs
```

```sh
SCANNER_ALLOWED_ORIGIN=https://你的InteSchool域名 node scripts/scanner-bridge.mjs
```

本地开发可使用 `http://localhost:5173`。所有跨域请求仍需来源与自定义请求头检查。

## 构建 Windows 安装包

发布工作流 `.github/workflows/scanner-installer.yml` 在 Windows runner 上使用 Node.js 22 官方运行时及 Inno Setup，生成自包含 x64 安装程序，上传到固定的 `scanner-bridge-latest` GitHub Release。使用工作流手动触发更新包；上传前需通过 Windows 安装与 HTTP 接口烟测。此安装包不包括设备专用驱动或 NAPS2；托盘菜单提供 NAPS2 官方下载入口。Windows PowerShell 5.1 用于托盘程序，随 Windows 10/11 提供，无需另行安装。

## 使用流程

1. 点击登录页“我要扫描”，绑定学校，点击“刷新设备”检查设备及接口类型；有多个扫描仪时从列表中选择。默认启用自动进纸双面采集，WIA 单面设备需要手动关闭双面。
2. 点击已发布答题卡，使用所选扫描仪批量采集（单批最多 40 页）。页面预览每张扫描图片，并尝试从整幅图及四个区域解析二维码（可适应二维码位置变化）。
3. 系统将二维码与所选试卷/讲义的稳定标识比对。**教师核对后点击“确认试卷并上传”**，将匹配的扫描件逐页上传。二维码未识别的页面会作为待处理异常卷保存；识别为其他试卷的页面会被阻止，必须改选正确答题卡重新扫描。
4. 已上传的扫描记录与原始图片会持久存储在平台。在“作业考试 → 考试管理 → 扫描件处理”可查看原图、人工关联学生，或保留尚不能关联的异常卷，后续再处理。上传时必须登录本校教师账号；未登录时仅可本机采集和下载。未上传的图像关闭页面后丢失。

当前实现**不会自动批改、读取学号或姓名、匹配笔迹/签名或生成成绩**。每次扫描批次需要教师主动确认后才会上传，并非硬件端的逐页流式后台上传。手写 OCR、签名模型和学生认领属于独立的识别与审核功能，需后续实现与实际样张验证。

## 排障

- 安装后看不到右下角图标：先检查 Windows 通知区域的「^」隐藏图标；从开始菜单运行「InteSchool 扫描桥接」，再检查任务管理器中是否有 PowerShell 运行 scanner-tray.ps1。应用日志位于 %LOCALAPPDATA%\InteSchool\Scanner\tray.log，服务日志位于同目录的 bridge.log。可通过安装包重新安装修复。
- 网页提示“无法连接本机扫描服务”：Windows 先安装桥接并点击“授权连接本站”，源码模式检查 Node 22 进程和网址来源配置、浏览器本地网络权限以及 `127.0.0.1:17380` 端口占用。Chrome/Edge 需要在站点权限里允许本机设备（loopback）访问，遇到权限弹窗不要误点“阻止”；无法安装或授权时改用上面的图片导入流程。
- 网页提示“未发现扫描仪”：Windows 在 NAPS2 GUI 中尝试切换 TWAIN/WIA 并检查系统设备管理器；Linux 使用 `scanimage -L` 检查 SANE 枚举。如果扫描仪仅提供 TWAIN，安装 Windows 设备驱动**并不等于** WIA 能访问它。
- 需要双面扫描却只找到 WIA：安装 NAPS2 并选择其 TWAIN 设备条目，或更新设备对应的 WIA 驱动；不能通过切换网页勾选框强行让单面设备变成双面。
- 显示驱动拒绝纸源、无法自动进纸、页序错误：检查进纸器/双面器是否真实支持及驱动纸源选项，再用 NAPS2 GUI 或厂商自带软件扫描测试。
- 已扫描但是没有图片：检查是否装纸、设备是否被其他程序占用及系统驱动设置。请使用目标设备进行实机测试，模拟测试无法保证各厂商驱动一致。

本机桥接只接受配置的单一来源和固定协议请求，服务没有远程执行任意命令的接口。扫描图片不由桥接写入平台；网页确认上传后，后端校验教师登录会话、CSRF、学校归属、答题卡发布状态及图片格式。单页文件大小不能超过 25 MiB；后端的部署上传限制也可能更低。
